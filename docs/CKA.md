## Setup Linux requirements (Ubuntu)

_Load Kernel modules_

```bash
cat > /etc/modules-load.d/kubernetes.conf <<EOF
overlay
br_netfilter
EOF

```bash
systemctl restart systemd-modules-load
```

_Configure Kernel Parameters_

```bash
cat > /etc/sysctl.d/99-kubernetes.conf <<EOF
net.ipv4.ip_forward=1
net.bridge.bridge-nf-call-iptables=1
net.bridge.bridge-nf-call-ip6tables=1
EOF
```

```bash
systemctl restart sysctl
```

## Kubernetes Cluster installation and setup

### Install kubeadm kubectl kubelet crictl

_Install gpg keys_

```bash
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.36/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
```

_Create Repo_

```bash
cat > /etc/apt/sources.list.d/kubernetes.list <<EOF
deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.36/deb/ /
EOF
```

_Install packages_

```bash
apt update
```

```bash
apt install -y kubeadm kubectl kubelet cri-tools
```

### Configure crictl

```bash
cat > /etc/crictl.yaml <<EOF
runtime-endpoint: "unix://var/run/containerd/containerd.sock"
image-endpoint: ""
timeout: 0
debug: false
pull-image-on-create: false
disable-pull-on-run: false
EOF
```

### Initialize the Cluster

_Initialize with options_

* Set the CIDR `--pod-network-cidr` which will match the CIDR set in the the CNI.
* Set `--patches` configure kubelet with a certificate signed by the Kubernetes
  CA instead of a self signed certificate. This is required for the
  metrics-server to talk securely to kubelet.

_Patches note that the file name follows the pattern set in patches_

```yaml
# /tmp/kubernetespatches/kubeletconfiguration.yaml
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
# Certificate settings
rotateCertificates: true # Automatically rotates kubelet client certificates
serverTLSBootstrap: true # Automatically bootstraps kubelet serving certificates
```

```bash
kubeadm init --pod-network-cidr=10.244.0.0/16 --patches /tmp/kubernetespatches/
```

_List the CSRs generated by Kubelet_

```bash
kubectl get csr
```

_Sign the CSR_

```bash
kubectl certificate approve $csr
```

### Using crictl

`crictl` is a command-line interface for managing containers in Kubernetes environments. It provides many commands familiar from the Docker CLI, along with Kubernetes-specific functionality, and interacts directly with container runtimes such as `containerd` and CRI-O.

_Install crictl_

If the kubernetes repositories were installed then crictl can be installed using apt.

```bash
apt update
apt install -y crictl
```

Configure `/etc/crictl.yaml` with the `runtime-endpoint` to stop receiving error messages.

```yaml
runtime-endpoint: "unix://var/run/containerd/containerd.sock"
image-endpoint: ""
timeout: 0
debug: false
pull-image-on-create: false
disable-pull-on-run: false
```

`crictl` Commands

```bash
crictl
crictl ps
crictl pods
crictl images
```

### Managing Node State

Mark node as unschedulable

```bash
kubectl cordon
```

Mark node as unschedulable and move all running Pods

```bash
# Remove pods that were not started from a DaemonSet
kubectl drain

# Remove pods that are part of a DaemonSet
kubectl drain --ignore-daemonsets

# Deletes data from emptyDir Pod volumes
kubectl drain --delete-emptydir-data
```

Restore the node

```bash
kubectl uncordon
```

* Using cordon or drain will set a taint on the nodes
* A taint is a restriction preventing Pods from running or being scheduled on a node.

To see the taint
```bash
kubectl describe node worker1.dev.site | grep -i taint
# Taints:             node.kubernetes.io/unschedulable:NoSchedule
```

## Node Maintenance Tasks

### Setup a Metrics Server

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
```

Metrics Server requires a valid TLS certificate when connecting to the Kubelet.

If the Kubelet is configured to generate a CSR and its certificate is signed by
the Kubernetes CA, no additional Metrics Server configuration for the metrics
server to connect to kubelet. This was done when the control plane and worker
nodes were initialized with kubelet config patches using `--patches`. Simply
sign the certificates and kubelet will pick up it's certificates.

```bash
kubectl get csr
```

```bash
kubectl certificate approve ${csr}
```

No restart is required if the above method is used.

By default, the Kubelet uses a self-signed certificate. In this case, configure
Metrics Server with:

`--kubelet-insecure-tls`

This disables Kubelet certificate verification.

```bash
kubect edit deployment metrics-server
```

Add `--kubelet-insecure-tls` argument to the metrics server:

```yaml
    spec:
      containers:
      - args:
        - --cert-dir=/tmp
        - --secure-port=10250
        - --kubelet-preferred-address-types=InternalIP,ExternalIP,Hostname
        - --kubelet-use-node-status-port
        - --metric-resolution=16s
        - --kubelet-insecure-tls
```

Restart the metrics server.

```bash
kubectl rollout restart deployment metrics-server -n kube-system
```

Test that the metrics server is running

```bash
kubectl top pods --all-namespaces 
```

More help is available for the metrics-server cli options by running:

```bash
podman run --rm registry.k8s.io/metrics-server/metrics-server:v0.9.0 --help
```

### Install etcdutl etcdctl

Choose a release from [https://github.com/etcd-io/etcd/releases/](https://github.com/etcd-io/etcd/releases/) or check the version of etcd running in your cluster. e.g.

`kubectl exec -n kube-system -it ${ETCD_POD} -- etcdctl version`


```bash
ETCD_VER=v3.6.8

# choose either URL
GOOGLE_URL=https://storage.googleapis.com/etcd
GITHUB_URL=https://github.com/etcd-io/etcd/releases/download
DOWNLOAD_URL=${GOOGLE_URL}

rm -f /tmp/etcd-${ETCD_VER}-linux-amd64.tar.gz
rm -rf /tmp/etcd-download-test && mkdir -p /tmp/etcd-download-test

wget ${DOWNLOAD_URL}/${ETCD_VER}/etcd-${ETCD_VER}-linux-amd64.tar.gz -P /tmp
tar xzvf /tmp/etcd-${ETCD_VER}-linux-amd64.tar.gz -C /tmp/etcd-download-test --strip-components=1 --no-same-owner

cp /tmp/etcd-download-test/etcdctl /usr/local/sbin/
cp /tmp/etcd-download-test/etcdutl /usr/local/sbin/
chmod 750 /usr/local/sbin/etcd*
```

### Backup etcd

_Install etcdctl etcdutl_

ETCDCTL_API=3 etcdctl --endpoints=localhost:2379 --cacert /etc/kubernetes/pki/etcd/ca.crt --cert /etc/kubernetes/pki/etcd/server.crt --key /etc/kubernetes/pki/etcd/server.key snapshot save /var/backup/kubernetes_etcd_$(date +%Y-%m-%d_%H-%M-%S).db

### Restore etcd

_Stop Static Pods_

```bash
mkdir /etc/kubernetes/manifests/stopped
mv /etc/kubernetes/manifests/*.yaml /etc/kubernetes/manifests/stopped
```

_Wait for static pods to stop_

```bash
watch crictl pods --namespace kube-system
```

_Move directory_

```bash
mv /var/lib/etcd{,$(date +Y-%m-%d_%H-%M-%S).old}
```

_Restore etcd data_

```bash
etcdutl snapshot restore /var/backup/kubernetes_etcd_${DATE}.db --data-dir /var/lib/etcd
```

_Start Pods_

```bash
mv /etc/kubernetes/manifest/stopped/*.yaml /etc/kubernetes/manifest
```

### Cluster Node Upgrades

_CKA search "Upgrading kubeadm clusters" in docs.kubernetes.com_

* Clusters can be upgraded from one minor version to another
* Skipping minor versions is not supported
* Manual updates to /etc/apt/source.list.d/kubernetes to the latest version
* The upgrade procedure is as such.
  1. The first upgrade is kubeadm binary.
  2. Upgrade the control plane.
  3. Upgrade the worker nodes.
* The cluster can run different minor versions.

#### Control Plane Upgrade

Setup for the latest kubernetes packages.

_In docs.kubernetes.com "Upgrading kubeadm clusters" there is a link "Changing the Kubernetes package repository". Use the same link for the Release.key_

```bash
cat > /etc/apt/sources.list.d/kubernetes.list <<EOF
deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:stable:/v1.36/deb/ /
EOF
```

Install the latest apt key

```bash
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.36/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
```

Upgrade kubeadm

```bash
apt-mark unhold kubeadm && \
apt-get update -y && \
apt-get install -y kubeadm='1.36.3' && \
apt-mark hold kubeadm -y
```

Check available version

```bash
kubeadm upgrade plan
```

Drain the node of all workloads

```bash
kubectl drain ${control_node} --ignore-demonsets
```

Gracefully shutdown kubeapi

```bash
killall -s SIGTERM kube-apiserver
sleep 20
```

Run the upgrade

```bash
kubeadm upgrade apply v1.36.3
```

_NOTE: On the other control plane nodes run `kubeadm upgrade apply` not `kubeadm upgrade plan`_

```bash
kubeadm upgrade apply
```

Upgrade and restart kubelet and kubectl

```bash
apt-mark unhold kubelet kubectl && \
apt-get update -y && \
apt install -y kubelet='1.36.3' kubectl='1.36.3' && \
```

Bring back the control node

```bash
kubectl uncordon ${control_node}
```

Check that the nodes are running again

```bash
kubectl get nodes
```

#### Worker nodes upgrade

Setup for the latest kubernetes packages.

```bash
cat > /etc/apt/sources.list.d/kubernetes.list <<EOF
deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:stable:/v1.36/deb/ /
EOF
```

Install the latest apt key

```bash
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.36/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
```

Upgrade kubeadm

```bash
apt-get update
apt-mark unhold kubeadm && \
apt-get update && \
apt-get install -y kubeadm='1.36.3' && \
apt-mark hold kubeadm
```

Check version

```bash
kubeadm version
```

Check kubeadm upgrade plan

```bash
kubeadm upgrade plan
```

Apply the kubeadm plan

```bash
kubeadm upgrade apply v1.36.3
```

Drain worker node

```bash
kubectl drain ${worker_node} --ignore-daemonsets
```

Upgrade kubelet & kubectl

```bash
apt-get update
apt-mark unhold kubelet kubectl && \
apt-get update && \
apt install -y kubelet='1.36.1-1.1' kubectl='1.36.1-1.1' && \
apt-mark hold kubelet kubectl
```


## Manage Security Settings

### Understanding Kubernetes Users

* A Role is a collection of verbs
  * create
  * list
  * etc ... 

* Roles give access to resources
* Rolebindings connect two different entities to a role
  * User
  * ServiceAccount
    * Pods

### Setup RBAC for service accounts

* A ServiceAccount is used to authorise Pods to get API info.
* All Pods have a default ServiceAccount which provides minimal access
* For more access, specific ServiceAccounts can be created
* ServiceAccounts don't have specific configurations
* The are used in RoleBindings to get access to specific roles
  
#### Configure ServiceAccount

1. Create a Pod with the standard ServiceAccount

```bash
kubectl run mypod --image=alpine --sleep 3600
```

2. Check current SA configuration.

```bash
kubectl get pods mypod -o yaml
```

### Replica Sets

In this section we will replicate a POD into multiple nodes.


_List available deployments_

List available deployments and choose one that can be replicated

```bash
$ kubectl get deployments
NAME                  READY   UP-TO-DATE   AVAILABLE   AGE
kubernetes-bootcamp   1/1     1            1           8m3s
```
The fields represented in deployments
* NAME - Name of the deployment
* READY - The current/desired replicas
* UP-TO-DATE - The number of replicas that have been updated to achieve the
  desired state.
* AVAILABLE - The number of replicas available to the end user.
* AGE - The amount of time the application has been running.


_List replica sets_

```bash
$ kubectl get rs
NAME                             DESIRED   CURRENT   READY   AGE
kubernetes-bootcamp-57978f5f5d   1         1         1       12m
```

The fields represented in the replica set output
* DESIRED displays the desired number of replicas of the application, which you
  define when you create the Deployment. This is the desired state.
* CURRENT displays how many replicas are currently running.

_Scale out the deployment_

```bash
$ kubectl scale deployments/kubernetes-bootcamp --replicas=4
deployment.apps/kubernetes-bootcamp scaled
```
